How you know what you can change
CPU load▼ A well with a border is a control. The border is what says "you can change this". A chevron means it opens a list; no chevron means you type or scrub it.
A bounded number gets a track. Opacity, scale and blur have an end; a slider shows where you are without a keyboard.
accent.cool #4da3ff No well means read-only. Spends has no border and no chevron anywhere in it, and it says so in its header. Nothing here is a target you can miss.
CPU load▼ Focus is an accent ring, not a browser outline. On a dark panel the default ring is invisible, so the accent marks the one focused control.
—▼ A control with nothing to offer still renders, greyed. The spec's rule: don't hide the field because this kind lacks it — hide nothing, disable what cannot apply.
One constraint worth knowing before this is designed further: the panels are imperative DOM, not React — 23 native <select>s and native input type=range today. The language above has to be achievable by styling those, or it means Reactifying the panel layer first. That is a real fork and I will bring it back as its own question.
