# The Panes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill plan 2's four rail slots with §5's panes — a Composition pane whose rows carry a kind glyph and a name, an Add pane rendering `insertGroups()` as units and primitives with the asset path absorbed into it, a Tokens pane where the paint and preset libraries get the surface `vg-153` says they lack, and a Document pane holding artboard, background, metadata and a read-only References — deleting the Assets slot, the Style tab and the panels' native controls, and discharging `vg-153` and `vg-094`.

**Architecture:** The panes are React components rendered where the imperative panels render today, and the factories keep their signatures so `editor-session.ts` keeps its construction sites: `createArtboardPanel`, `createPalettePanel`, `createTypePresetPanel` and `createNewObjectPanel` each create a React root inside the host they are given — the idiom plan 3 established for `createSelectionInspector`. Nothing is re-derived: every list renders a registry that already owns its membership (`insertGroups()`, `CARD_LIBRARY`, `SHAPE_KINDS`, `CHART_FAMILIES`, `OBJECT_ACTIONS` + `actionEnabled`, `paletteTokenUsage`, `reassignPaletteToken`, `reassignTypePresetToken`), and every fact comes through a port the session already passes. `createAssetPanel` is deleted and its import/place/remove path becomes the Add pane's own file section. Fabric stays behind the bridge: no object is mirrored into React state, and the one new projection the Tokens pane needs is a preset **id** produced by the existing `typePresetOf` reader.

**Tech Stack:** TypeScript, React 19, Base UI, Tailwind v4 (`@theme`), Biome 2.x, Vitest (jsdom), Playwright, Node ESM scripts.

**Spec:** [`docs/superpowers/specs/2026-10-08-editor-design-language-design.md`](../specs/2026-10-08-editor-design-language-design.md) — §2.2, §2.3, §5 (all four panes), §8, §12 row 4, §13, Invariants, Acceptance
**Normative companion:** [`docs/design/design-language.md`](../../design/design-language.md) — §2, §3, §4, §5, §6 (the card-diagram / group-glyph rule), §7.3, §8, §9, §10
**Reference:** [`docs/design/mockups/editor-shell.html`](../../design/mockups/editor-shell.html) and [`README.md`](../../design/mockups/README.md) for what a mockup is and is not
**Decision:** [`0039`](../../decisions/0039-the-editor-ui-is-react-and-only-the-canvas-is-imperative.md), [`0030`](../../decisions/0030-one-read-only-surface-per-resolved-answer.md)

## Global Constraints

- **No behaviour changes, with one named exception.** `§2.3` holds for all four panes: same fields, same eligibility gates, same refusals, same read-only markers. The exception is ruled by the spec and is this plan's whole point in the Tokens pane — `§5.3`'s `vg-094` binding, which changes what the preset chooser *is* (bound to the selection, not defaulted to the first declared preset). Nothing else in this plan changes a rule. State the exception in the commit that lands it.
- **Where a test locates imperative internals this plan moves, it is re-pointed at the React surface in the same commit**, and a re-pointed locator must be shown to fail when the behaviour it guards is disabled before it is trusted. The heavy ones: `panel-labels.spec.ts` (25 references), `editor.spec.ts`, `reference-theme.spec.ts`, `shell-appearance.spec.ts`, `glass-authoring.spec.ts`, `clip-parity.spec.ts`, and the two helpers `editor-canvas.ts` / `rebuild-driver.ts`.
- **The factories keep their signatures.** `createArtboardPanel(host, …)`, `createPalettePanel(host, …)`, `createTypePresetPanel(host, …)` and `createNewObjectPanel(host, …)` are still constructed exactly where `editor-session.ts` constructs them; each renders React inside the host it is given. `revealTypePresets` reaches the preset list through `this.#types.root`, so the root element and its `scrollIntoView` contract survive — but the reveal must **open the Tokens slot** first, since a hidden pane cannot be scrolled to (Task 7).
- **`data-vigilia-*` attributes are hard contracts.** Every attribute the panels carry today is preserved on a focusable element of the React surface unless the task names it as re-pointed. `[data-vigilia-panel="layers"]` stays the Composition pane's section (plan 2 ruled it), `[data-vigilia-panel="style"]` stays the References section, and the accessible names `Colour token` and `Type preset` stay on their choosers verbatim.
- **One owner per concept.** `insertGroups()`, `CARD_LIBRARY`, `SHAPE_KINDS`, `CHART_FAMILIES`, `OBJECT_ACTIONS`, `actionEnabled`, `arrangeActions()`, `paletteTokenUsage`, `reassignPaletteToken`, `reassignTypePresetToken`, `typePresetOf`, `resolveToken`, `resolveTypePreset` and `style.ts`'s document resolution keep theirs. No surface re-spells a membership; no surface decides eligibility for itself.
- **Fabric stays imperative and no object is mirrored into React.** Every pane reads ids, names, counts, eligibility and one preset id. A `FabricObject` in a component's props is the defect.
- **Persist authored state only.** Which slot is open, the scroll offset, the hovered/focused row and the selected list row are transient. No pane adds a field to the document.
- **Scales and roles only.** Every value comes from plan 1's tokens and the bible's roles. **Every file this plan converts joins `scripts/design-tokens.gated.json`'s `gated` list in the same task** — the ratchet is seeded as work lands, never afterwards. A swatch well showing a paint value is the one place a literal colour is data rather than a decision; where the ratchet flags it, the file gets a narrow, reasoned allowance rather than the rule being weakened.
- **No new dependency.** React 19, Base UI and Tailwind v4 are present; `0038` and `0039` stand. The pane's directory is named for its responsibility (`panes/composition/`, `panes/add/`, `panes/tokens/`, `panes/document/`) — not `helpers`, `common`, `utils`, `shared` or `internal`.
- `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` are enabled. Refuse invalid numeric input; never coerce it to zero. No licence headers; comments are 1–3 lines and explain *why*. 500 lines is a signal and 800 is a stop.
- **Register rows.** This plan **discharges** `vg-153` and `vg-094` and **absorbs the insert half of `vg-154`**, which **stays open** with its detail updated (Task 12). `vg-161`, `vg-172`, `vg-185` and `vg-192` are not answered here. `vg-121`, `vg-122` and `vg-089` are archived `verified`: do not re-open them.
- Run from `src/web/`; the scripts are `package.json`'s. Stage explicit paths; never `git add -A`. Conventional Commit titles.
- **Playwright previews built bundles.** Rebuild after any source change and after reverting a deliberate break. `VIGILIA_CAPTURE=1` and `--workers=1` for any capture; capture only actions registered in `docs/evidence/screenshots/README.md`.
- **A new test must be shown to fail when the behaviour it guards is disabled**, before it is trusted. Every task below states its red proof.

## Review Focus

The spec implies these and no task's tests exercise them. Each is pinned to the task that owns its code. **Five, and only five**: these are the failures that are silent and owned by nobody. The ones this list drops (`§5.1`'s second heading, the group glyph that depicts the group, the two-hundred-row cost, a hard-coded card name, a ninth card unit, a swatch writing its resolved colour, a resolution wearing a well, a ratchet seeded to pass, a capture of the wrong screen) each already carries a task-level red proof of its own, so they are pinned where the code is rather than listed here.

1. **A field lost by omission in the artboard rewrite.** `panel-labels.spec.ts` asserts that no *rendered* control is unnamed; it says nothing about a control that is simply absent, and the artboard panel is 594 lines of fields, several of which only render in one branch (a background asset chosen, a resolution list, a size note). → Task 8.
2. **Hover as the only path to a control.** The row's rename, eye and lock appear on the attended row. A pointer-only gate leaves a keyboard author with three inaccessible controls, and the existing attendance rule is the thing that breaks silently when the row is re-cut. → Task 2.
3. **A binding that still shows a default.** `vg-094`'s defect is not "the wrong preset is selected" — it is that a *default* and an *answer* are indistinguishable. A fix that makes the chooser follow the selection but still silently shows the first preset when the selection carries none has moved the defect rather than removed it. → Task 7.
4. **A read-only section inferred from absence.** `§5.4` and bible §5.1: References says it is read-only in its own header, before it is opened. Absent controls and a refusal look identical to an author, and only one of them is true. → Task 9.
5. **The import path's two outcomes, and the asset with no object.** An image is declared *and placed*; a video or a font is declared only (`isPlaceable` accepts image and svg), so it never becomes a layer. A file section that lists only placed images leaves a font imported once with no way to remove it — `vg-154`'s own consequence, and nothing fails while it is missing. → Task 4.
