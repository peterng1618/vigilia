# Keyboard — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every action an author can run says which chord runs it — in the tooltip of the
control they are pointing at, in the menu row they are reading, and in one sheet `?` opens.
The canvas carries **one** contextual toolbar instead of two, and both render from the
registry that already owns which actions exist.

**Architecture:** Three owners, and only one of them is new surface. **One** — the chord
vocabulary — already exists and is **module-private**: `shortcut-manager/index.ts` holds
`PRODUCT_SHORTCUTS`, a list of bindings with no display form and no labels. It gains an
export, a platform-aware renderer and a label projection, and the dispatcher itself changes
in exactly one other way (a modal owns the keyboard). **Two** — the surfaces — already
exist and already render from the registry: the canvas dock (`OBJECT_ACTIONS`) and the
arrange strip (`arrangeActions()`). §7 says there is *one* contextual toolbar, so the two
become one, and every control in it shows its chord in the tooltip the editor already owns.
**Three** — the `?` reference — is a new Radix `Dialog` (spec §8's ruling, decision
[`0033`](../../decisions/0033-new-primitives-are-radix-the-tooltip-is-not.md)) rendered
from the same projection the tooltips read, opened through a new
`EditorSessionOptions.onShowShortcuts` callback, which is the shape every other modal
prompt in this session already uses.

**Tech Stack:** TypeScript, React 19 for the shell chrome, `@radix-ui/react-dialog` (MIT,
**the one new dependency** — §8's ruling; the decision note records why the other two
answers were rejected), the editor's own hand-owned tooltip (`editor-shell/controls/tooltip.ts`,
unchanged as a mechanism), Vitest + jsdom for the projections and the chrome, Playwright
against built bundles for the chords a browser reports.

**Spec:** [`../specs/2026-10-03-dashboard-authoring-design.md`](../specs/2026-10-03-dashboard-authoring-design.md)
— plan 7 of 9. Read §7 to its end (`:398-402`), then §8 (`:404-449`) because this plan is the
first to act on its ruling, the Sequencing table row 7 (`:473`), Invariants (`:482-496`),
Non-goals (`:498-504`) and Acceptance (`:506-543`). The one test every task is judged by is
the spec's own: *does this change remove a step, or does it remove a freedom?*

## What is already true — do not rebuild

Verified against the source at `664bd820`, the commit this plan was written from. **A task
that rebuilds any of this has misread the plan.**

1. **The chord table exists and is private, and it is a list, not a map.**
   `shortcut-manager/index.ts:31-65` — `const PRODUCT_SHORTCUTS: readonly ShortcutBinding[]`.
   Each binding is `{ key, modifier, shift?, action }` (`:23-29`). It is **not exported**;
   `ProductShortcutId` (`:2-21`) **is**. The union has **19** members and the table binds
   **18** of them: `view.exit-group` (`:21`) is a member with no product binding, so the
   union is one larger than §7's "eighteen of them were on the canvas at once". **A count
   read off `:2-21` and a count read off the table are two different numbers**, and Task
   1.1 pins the table's while `SHORTCUT_LABELS` is total over the union's.
2. **Several actions answer to more than one binding, and that is deliberate.**
   `edit.redo` is `Ctrl+Shift+Z` *and* `Ctrl+Y` (`:38`, `:42`, with the comment saying why);
   `edit.delete` is `Delete` and `Backspace`; `canvas.front` / `canvas.back` are the bare
   `]`/`[` *and* the shifted `}`/`{` a browser actually reports under Shift (`:49-55`).
   A display that shows one chord per action is teaching half the truth.
3. **`view.exit-group` is context-only and must stay off any display.**
   `CONTEXT_SHORTCUTS` (`:69-71`) holds `Escape`, and the comment says it is "dispatched
   here but never displayed by a menu or tooltip". `editor-session.ts:497-500` repeats it.
4. **The editor already has one hand-owned tooltip and it is not React.**
   `editor-shell/controls/tooltip.ts` — `tooltip({ trigger, text })`, portalled to
   `document.body`, class `.editor-shell-tooltip`, one open at a time. The dock's comment
   (`canvas-dock.tsx:16-20`) records the reason it is a DOM function: the selection
   inspector builds elements with `document.createElement` and never sees React.
5. **The canvas has *two* action surfaces and both already read the registry.**
   `CanvasDock` (`canvas-dock.tsx:51-84`) renders `OBJECT_ACTIONS` **filtered** by
   `actionEnabled(bridge, action.id)`, gated by a `data-visible` attribute. `ArrangeToolbar`
   (`shell-layout.tsx:132-161`, `data-vigilia-arrange-toolbar`) renders all of
   `arrangeActions()` **always**, disabled when `arrangeEligible` refuses, with a native
   `title={label}` rather than the shell's tooltip. §7 says there is one; Task 2.3 makes that
   true, and the reading it adopts is stated in that task.
6. **`OBJECT_ACTIONS` carries no shortcut, and its ids are not the shortcut ids.**
   `object-actions.ts:52-58` — `{ id, label, icon, eligible, run }`. `id` is an
   `ObjectActionId` (`:37-50`): `duplicate`, not `edit.duplicate`; `front`, not
   `canvas.front`. The association does not exist anywhere and Task 2.2 creates it.
7. **Every visible word is in `ui-copy.ts`.** `actions` (`:363-378`), `arrangeLabels`
   (`:380-389`), `dock.label` (`:398`), `canvasMenu.label` (`:401`),
   `arrangeToolbar.label` (`:403`). Nothing there names a key, and the repo contains **no
   `<kbd>` element**.
8. **The editor's dialogs are the platform's, three times over.**
   `document.createElement("dialog")` + `showModal()`, class `vigilia-dialog`, styled at
   `editor-shell/editor-shell.css:761-788`: `new-document-chooser.ts` (`chooseArtboardSize`,
   called from `editor-session.ts:941`), `persistence-manager/index.ts:117`,
   `theme-library-dialog.ts:110,298`. **This plan ports none of them** — decision `0033`
   hands them to plan 9.
9. **The portalled-popup palette problem is already solved, and this plan must not re-solve
   it.** `palette.ts:35-49` writes `data-shell-palette` onto `document.documentElement`
   *because* portalled surfaces are siblings of `#app`. A Radix portal to `document.body`
   inherits it. **Do not add an element parameter to `applyShellPalette`.**
10. **The `?` reference has no click affordance, and this plan does not add one.** §7 names
    three deliverables and a header button or Help menu is not among them; chrome is plan
    9's. See *Out of scope*.

## Global Constraints

Copied from `AGENTS.md`, from the spec and (where it states them) verbatim. Every task's
requirements implicitly include this section.

- **Unit-test pure decisions and contracts; browser-test wiring and visible behaviour.**
  Visible behaviour requires rendered/browser inspection, not only object counts or geometry
  assertions. A green DOM test is not a proof that an author sees a chord in a tooltip.
- **A new regression test must fail when the fix is disabled before it is trusted.**
  Every task below that adds one says, in its own steps, how it was disabled and what
  failed. **A prescribed break that does not break is a plan defect, not a passing test** —
  find a break that fails, observe it, restore it, and say in your report what the
  prescribed break actually did.

  `npx vite build packages/editor` from `src/web/` **before** the browser run, and again
  after reverting a deliberate break. Run Playwright as a CLI, always `--workers=1`, and
  read results **from the JSON report file** — pass `--reporter=json` with
  `PLAYWRIGHT_JSON_OUTPUT_NAME` under `src/web/test-results/`. Never run a spec through the
  shared MCP browser, and never read a pass/fail summary off stdout.

  `./node_modules/.bin/biome lint ..`** — there is no working `npm run lint` (the script
  runs `biome lint ..` but the constraint is the binary, and `biome check` **is not a gate**

## Review Focus

The spec is a vision document: it says what an author must be able to do, not everything the
software will meet, and its silence is not permission. These are the five inputs most likely
to bite a person using this software, most likely first, and **each one is pinned by a test
in the task that owns the code** — the task is named in brackets.

1. **A macOS author.** The dispatcher accepts `ctrlKey` *or* `metaKey` on every platform
   (`shortcut-manager/index.ts:76`), so the binding is fine everywhere — but the chord
   *displayed* is a choice, and every test in this plan runs on Windows. Shipping `Ctrl+Z`
   to a Mac is invisible on the machine that produced it and teaches the wrong key to the
   author reading it. A person expects the chord their own keyboard has. [Task 1.2 — pinned
   by a test that stubs `navigator.userAgent` to a Macintosh and asserts the glyphs, and a
   second that asserts the Windows spelling.]
2. **A modal that does not actually own the keyboard.** Radix's Dialog and the native
   `<dialog>` both make the page behind them inert *to the pointer and to focus*, and
   neither touches a `window`-level `keydown` listener. The editor's dispatcher is exactly
   that (`shortcut-manager/index.ts:114-116`), so with the `?` sheet open `Ctrl+Z`, `Delete`
   and the arrow nudge would all still edit the document the author is reading about. A
   person expects a modal to be modal. [Task 3.3 — pinned by a test that a binding fires
   with no dialog open, is refused while one is, and fires again once it closes.]
3. **Escape while the sheet is open.** `view.exit-group` is registered on `Escape` at the
   window (`editor-session.ts:497-500`), and the dialog closes itself on the same key. The
   author dismisses a reference and loses their place in the group they were editing. A
   person expects one keypress to have one effect. [Task 3.3 — the same deferral answers it;
   pinned by a test that `Escape` still reaches `view.exit-group` when nothing is open.]
4. **An action with more than one binding.** Four of the eighteen do (`edit.redo`,
   `edit.delete`, `canvas.front`, `canvas.back`). A reference that shows one chord teaches
   half the truth — and the tooltip that renders both grows a longer string inside a popup
   that is capped at 280 px and, when it outgrows its placement, lands on the control it
   belongs to and suppresses its own hover (`tooltip.ts:20-31` records that whole failure).
   A person expects to see every key that works and to be able to read the popup that says
   so. [Task 1.2 renders every binding; Task 2.1 pins that the popup is still one element,
   still readable, and not sitting on its trigger.]
5. **A binding in the table with no word, or an action whose bindings vanish.** The sheet is
   a projection of `PRODUCT_SHORTCUTS`, so a `ProductShortcutId` added without a label
   simply disappears from it, and a binding deleted by hand quietly shortens it — both
   silently, in the one surface whose whole job is to be complete. A person expects the
   sheet to list every action the product has. [Task 1.1 pins the label map as a `satisfies`
   over the id union so a missing word is a compile error and not a missing row; Task 1.3
   pins that the sheet's row count is *derived* from the table rather than restated, so the
   two cannot drift.]

```ts
export interface ShortcutBinding {
  readonly key: string;
  /** A binding with no modifier always defers to a focused text field. */
  readonly modifier: boolean;
  readonly shift?: boolean;
  readonly action: ProductShortcutId;
}

export const PRODUCT_SHORTCUTS: readonly ShortcutBinding[] = [
  // …the table as it stands, unchanged…
];

/**
 * The distinct actions the table binds, in the table's own order.
 *
 * §7's reference is a list of *actions*, so the four actions bound twice
 * (`edit.redo`, `edit.delete`, `canvas.front`, `canvas.back`) appear once — the
 * second chord is a property of the action, not a second row. The order is the
 * table's rather than sorted, because the table is grouped by where the action
 * lives and that grouping is what the sheet's headings follow.
 */
export function productShortcutIds(): readonly ProductShortcutId[] {
  const seen = new Set<ProductShortcutId>();
  for (const binding of PRODUCT_SHORTCUTS) seen.add(binding.action);
  return [...seen];
}
```

/**
 * How a shortcut reads: the platform's caps, the words for the keys that have
 * none, and the projection §7's tooltips and its `?` sheet both render.
 *
 * The table's *membership* is `index.ts`'s and stays there. This module only
 * reads it, which is why nothing here re-spells a `ProductShortcutId` — a
 * second table would agree until someone added a binding to one of them.
 */
import { uiCopy } from "../ui-copy.js";
import {
  PRODUCT_SHORTCUTS,
  type ProductShortcutId,
  type ShortcutBinding,
} from "./index.js";

/** The part of an action id before its first dot: the group an action lives in.
 *
 * A *reading* of `ProductShortcutId` rather than a second copy of it, so the id
 * union keeps one owner (`index.ts`). It is proved total by the `satisfies` on
 * `uiCopy.shortcuts.groups`: a prefix with no group word is a compile error, and
 * a group word for a prefix no action carries is one too.
 */
export type ShortcutPrefix = ProductShortcutId extends `${infer P}.${string}`
  ? P
  : never;

/** The caps in force on this platform.
 *
 * `navigator.userAgent` is the only platform signal universally available;
 * `navigator.platform` is deprecated and `userAgentData` is Chromium-only, so
 * neither is a better answer. `ponytail:` the ceiling is a UA sniff — it is
 * wrong for a spoofed UA and for an iPad that reports itself as a Macintosh,
 * and the upgrade path is `navigator.userAgentData.platform` behind this same
 * function once the browser floor allows it.
 */
export function usesCommandKey(): boolean {
  return /mac|iphone|ipad/i.test(navigator.userAgent);
}

function caps(): { readonly modifier: string; readonly shift: string } {
  return usesCommandKey() ? uiCopy.shortcuts.mac : uiCopy.shortcuts.other;
}

/** The cap a binding's key prints.
 *
 * A single letter is uppercased, because that is what is printed on it. Any
 * other single character is printed as the browser reports it and the Shift cap
 * is **omitted**: `index.ts:49-54` binds `{` and `}` because Shift is what makes
 * the browser report the shifted character, so `Ctrl+Shift+}` would name a key
 * that does not exist. Named keys come from `uiCopy.shortcuts.named`, and a key
 * with no entry and no character on it returns `undefined` rather than its own
 * name — the caller drops the action instead of printing `ctrl+f13`.
 */
function keyCap(key: string): string | undefined {
  const named = (uiCopy.shortcuts.named as Record<string, string>)[key];
  if (named !== undefined) return named;
  if (key.length !== 1) return undefined;
  return /[a-z]/i.test(key) ? key.toUpperCase() : key;
}

function chord(binding: ShortcutBinding): string | undefined {
  const key = keyCap(binding.key);
  if (key === undefined) return undefined;
  const { modifier, shift } = caps();
  const parts: string[] = [];
  if (binding.modifier) parts.push(modifier);
  // A shifted *character* carries its own shift; a shifted *letter* does not.
  if (binding.shift === true && /[a-z]/i.test(binding.key)) parts.push(shift);
  parts.push(key);
  return parts.join(usesCommandKey() ? "" : "+");
}

/**
 * Every chord this action answers to, in the table's own order, joined by the
 * product's own separator. An action the table does not bind returns `""`.
 */
export function shortcutLabel(action: ProductShortcutId): string {
  const rendered = PRODUCT_SHORTCUTS.filter(
    (binding) => binding.action === action,
  )
    .map(chord)
    .filter((value): value is string => value !== undefined);
  return rendered.join(uiCopy.shortcuts.alternativeSeparator);
}

/** Whether the `?` sheet is open, as external state.
 *
 * The dispatcher lives in `EditorSession`, which never sees React, so the
 * gesture has to reach the chrome through a subscription rather than a prop —
 * the same shape `SelectionStore` has, for the same reason.
 */
class SheetStore {
  #open = false;
  readonly #listeners = new Set<() => void>();
  readonly subscribe = (listener: () => void): (() => void) => {
    this.#listeners.add(listener);
    return () => this.#listeners.delete(listener);
  };
  readonly get = (): boolean => this.#open;
  set(open: boolean): void {
    if (this.#open === open) return;
    this.#open = open;
    for (const listener of this.#listeners) listener();
  }
}
