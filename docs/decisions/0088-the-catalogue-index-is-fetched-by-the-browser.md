# 0088 — The catalogue index is fetched by the browser, and its shape has one owner in renderer-core

- **Date:** 2026-10-21
- **Status:** accepted
- **Paths:** `src/web/packages/renderer-core/src/theme/`
  `src/web/packages/host/src/catalogue/` (neither is a watchlisted owner; this
  note claims them because they are the two the decision creates)

## The problem

Phase C of `2026-10-12-theme-store-design.md` gives the store mode its **Online**
half: a read-only browse of a public GitHub-hosted catalogue whose listing is one
static file, `index.json`, generated by an Action and carrying each item's derived
facet record.

The shape worth solving is **where a remote document is acquired, and who owns its
wire shape**, when the document is one the product itself publishes and the two
runtimes available disagree about caching. The editor's browser has a real HTTP
cache; Node's `fetch` has none. The host owns scheduling, buffering and fallback for
*telemetry acquisition from hardware providers* — a rule that reads as though it
applies here and, on inspection, is about a different kind of thing.

The second half is quieter. The file is written by an Action running in the catalogue
repo and read by the editor in this one, so its shape has **two producers and one
consumer**, and the spec's own sentence about the facet record (line 505) already
states the rule for the other shared derivation: it lives in `renderer-core`, "because
that is the only layer both producers can import".

## Rung 1 — Vigilia

Searched: every `fetch(` in `packages/`; `If-None-Match`, `ETag`, `Cache-Control`,
`cache: "` across `packages/`; `AbortController`/`signal:` in the editor and host; the
host's route table; `renderer-core`'s dependency set and its `"//"` note.

Found: **the editor already fetches a third-party CDN from the browser, on the same
CDN the spec proposes for thumbnails.** Three sites — `editor-document.ts:586`,
`font-preview.ts:39`, `font-specimen-cache.ts:67` — all `cdn.jsdelivr.net/fontsource`,
reached from `font-trios.generated.ts`'s `sourceUrl` values, and `editor.spec.ts:2175`
already routes that URL in Playwright. Option A is not a new kind of thing here.

**The host has never made an outbound third-party request.** Its only two `fetch`
sites are `lhm.ts:105` and `lhm-launcher.ts:148`, both `http://127.0.0.1:8085`. A
host-fetched catalogue would be the first.

**Nothing in this repo revalidates.** No `If-None-Match` is ever sent, no `ETag` read,
no `fetch` passes a `cache:` option; every hit outside `@types/node` is the host
*setting* `cache-control` on its own routes.

**The pattern that does exist** is `font-specimen-cache.ts`'s `createSpecimenCache`
(line 51): a per-key resident map plus an in-flight map (54–55, dedupe 62–63), failure
tolerance (86–89), an **injectable `fetch`** (25) so a dom test drives it, and a
permanent `release()` (100–107). It has no TTL, no `ETag`, no retry and no timeout —
and the editor has no request timeout anywhere today.

**No owner for "a remote JSON index" exists. This is the first.** The nearest is
`ItemSource` (`store-mode/local-source.ts:54`), whose docblock names this case — "a
second kind is a second source rather than a rewrite of this tab" — and
`region.tsx:571-579` already carries the phase-C comment: the online half lists
nothing rather than the library under another name.

`renderer-core` has **zero network code**; its one dependency is `echarts`.

## Rung 2 — dependencies

Searched: every `package.json` in the workspace.

Found: **no HTTP client** (no axios/ky/got/undici), **no query or cache library** (no
TanStack Query, no SWR), **no schema validator** (no zod/ajv/valibot). Validation here
is hand-rolled — `fabric-envelope-validate.ts` is 41 KB of it.

`renderer-core`'s `"//"` forbids Fabric and editor UI in that package, not `fetch`; its
dependency set is `echarts` alone. The host's `"//"` records the house rule for this
class of addition: a runtime dependency needs a `THIRD-PARTY-NOTICES.md` entry first.

## Rung 3 — platform

Searched: MDN's *CORS-safelisted request header* and `RequestInit`; and measured both
candidate routes from this box.

Found: **CORS-safelisted headers are exactly `Accept`, `Accept-Language`,
`Content-Language`, `Content-Type`, `Range`.** `If-None-Match` is not among them, so a
script that sets it makes the request non-simple and triggers a preflight.

**Neither route permits it.** `raw.githubusercontent.com` answers the preflight
**`403`** with no `Access-Control-Allow-Headers` at all; `cdn.jsdelivr.net` answers
`200` and *also* sends none. **So the app cannot force a conditional request.** What it
can do is let the browser's own cache revalidate, which it does from the network stack
rather than from script — and therefore fires no preflight.

| Concern | Browser `fetch` | Node `fetch` |
|---|---|---|
| cache | owned — the HTTP cache stores under `max-age=300` | **not owned — no HTTP cache exists** |
| revalidation | owned — the cache issues the conditional request itself | not owned — `If-None-Match` by hand |
| retry, dedupe | not owned | not owned |
| abort/timeout | owned *given a signal*; `fetch` has no timeout parameter | same |

The sharp consequence: on the raw path `max-age=300` means a browser-direct fetch
makes **no request at all** for five minutes, and revalidates in `VS0` after. The same
header buys the host nothing, so a host route would hand-write a TTL, an `ETag` store,
`If-None-Match`, a last-good body, a stale-on-error policy, a timeout and a retry.

**`Vary: Authorization,Accept-Encoding` is on the raw path and only there.** With phase
E's stored token, a cache keyed on URL alone is wrong — a fact that lands on whichever
side does the caching.

## Rung 4 — ecosystem

Searched: jsDelivr's README (the docs site is a JS-rendered SPA and returned only its
nav); GitHub's REST rate-limits page; and measured four comparable static indexes —
`formulae.brew.sh/api/formula.json`, `registry.npmjs.org/react`,
`pub.dev/api/packages/http`, and Home Assistant's `glossary.yml` on the raw path.

Found: **every one is a single static index served with a `Cache-Control` plus a
validator, and every one is CORS-open.** None uses a REST API or a package manager for
its listing, and none of the four clients needs a library for conditional GET — each
lets the HTTP stack do it. TTLs cluster at 120–600 s, so the raw path's 300 is
mid-range rather than an outlier. Homebrew's index is **32 MB** fetched whole and
filtered client-side, which is the size the spec's sharding upgrade path exists for and
four orders of magnitude above a catalogue of a few hundred items.

Two measured details that shape the client: **a raw 404 carries no `Cache-Control` and
no `ETag`**, so a mistyped path is never negatively cached and the client's own failure
state is what stops a retry loop; and jsDelivr's thumbnail freshness is decided by
**which ref the Action writes into `index.json`** — a branch is 12 hours at the edge
and 7 days in the client's cache, a pinned semver tag is a year and `immutable`.

GitHub's contents API is a **metered** resource (60/hour per IP, measured
`X-RateLimit-Limit: 60`), while the raw path carries no `x-ratelimit-*` at all.

**NOT ESTABLISHED:** whether a library for conditional GET over a static index exists —
the search tool was unavailable and no such library was found by inspection. What is
established is that none of the four ecosystems above needs one.

## Rung 6 — probe

Measured from Git Bash on this box, 2026-10-21, against `github/gitignore`'s
`Node.gitignore` — a small, public, unrelated file.

`raw.githubusercontent.com`, plain GET: `Cache-Control: max-age=300`, a **strong**
`ETag` (`"38be65a3…"`), `Access-Control-Allow-Origin: *`, `Vary:
Authorization,Accept-Encoding`, `X-Cache: HIT`, no `Age` (`Source-Age: 0`).

The same URL with that `ETag` as `If-None-Match`: **`304 Not Modified`, no body,
`VS0`.** Revalidation is real and costs nothing.

The same file through jsDelivr: `public, max-age=604800, s-maxage=43200`, a **weak**
`W/"…"` tag, `Age: 4139`, `x-jsd-version-type: branch`; its conditional GET also
answers `304`.

Preflight asking for `if-none-match`: raw **`403`**, jsDelivr `200` — **neither sends
`Access-Control-Allow-Headers`.**

A raw 404: `Access-Control-Allow-Origin: *` but **no `Cache-Control` and no `ETag`**.
jsDelivr's 404 declares `no-cache, no-store, must-revalidate`.

The raw `ETag` is strong and opaque; **what it hashes is NOT ESTABLISHED** (not the
body, not the body normalised, not the git blob, not the blob's sha1 in any of four
spellings). It is honoured, which is the load-bearing fact.

The spec's five "Measured 2026-10-21" claims about these routes were re-measured and
all five hold.

## Rung 7 — build

Option A is **one new file** (`store-mode/online-source.ts`, implementing the existing
`ItemSource`) and **one touched** (`region.tsx`, whose phase-C comment becomes real and
which is *not* on the watchlist), plus the shape's owner in `renderer-core`. No TTL, no
`ETag` store, no stale-on-error, no retry, no timeout — the browser's cache is the whole
mechanism, and what is not built is named rather than assumed.

## Decision

**The editor's browser fetches `index.json` from the raw path, and the index's wire
shape is owned by `renderer-core/src/theme/catalogue-index.ts`.**

The reason is measured rather than architectural: **the browser revalidates
conditionally and for free against a server that answers `304` in `VS0`, and Node has
no HTTP cache to do it with.** Option B would re-implement, by hand, four things the
platform already owns, and would add a cache key that `Vary: Authorization` makes wrong
the moment phase E stores a token. `AGENTS.md`'s "the host owns scheduling, buffering
and fallback" is about telemetry acquisition from hardware providers — where
`providers/` is the watchlist entry — and not about a static file this product
publishes to a CDN.

The shape goes in `renderer-core` for the reason the spec gives for the facet record:
it is the only layer both producers can import, and `index.json` carries that record
per item. **No network code enters that package** — a type and a parser are inert, and
`fetch` is called from `store-mode/`, in the editor.

**Freshness is the origin's `max-age=300` and nothing else.** The app does not set a
`cache:` option, does not store an `ETag`, and cannot force revalidation even if it
wanted to (rung 6). The spec's "a favorite count is at most five minutes behind" is
therefore the contract, and a client that wants fresher has to change the route rather
than the code.

**Consequences to carry:** a 404 is never negatively cached, so the client's failure
state — `region.tsx`'s existing "a failed listing is not a fact about the library",
which leaves the listing unset rather than drawing an empty catalogue — is what stops a
retry loop; thumbnails' freshness is a decision inside the Action (branch vs pinned
tag), not inside the client; and the shape is parsed strictly, with a malformed entry
skipped and counted rather than failing the listing, because the spec's rule is that a
client which cannot parse an item "must skip it and say so, not fail the listing".
